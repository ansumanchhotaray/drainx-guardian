I have this architecture in mind for the project.

There would be an HTTP client on the ESP32 module (which will have all
the sensors connected to it) that pushes sensor data via HTTP POST whenever readings
are taken.

The controller laptop will run a Wi-Fi Mobile Hotspot to provide a
constant local IP address for the ESP32.

There would be a Python FastAPI web server on the laptop that receives the data directly from
the ESP32 and displays it on its own website UI interface.

It should also detect the garbage in the camera feed since this is for
this device which can detect garbage and clean but we don't have the
cleaning mechanism yet, so we will just display the things.

The sensor connection approach is now documented in `WIRING_GUIDE.md`.

We have camera sensor, turbidity sensor, ph sensor, and also temperature sensor.

* Extended Architecture & Integration Plan

** 1. Microcontroller Subsystem (Two-Board Architecture)
To overcome the ESP32-CAM's hardware limitations (specifically the conflict between Wi-Fi and ADC2 pins), the system uses two separate ESP32 boards:

*** A. Camera Node (ESP32-CAM)
- **Role**: Dedicated exclusively to video streaming.
- **Software**: Runs `Guardian/CameraNode.ino`. Connects to the Wi-Fi hotspot and hosts an **MJPEG-over-HTTP stream** on port 81 (`/stream`). This uses a persistent HTTP connection with `Content-Type: multipart/x-mixed-replace`, which continuously pushes JPEG frames without ever closing the connection.
- **Hardware**: AI Thinker ESP32-CAM module.
- **Note**: The Python backend *pulls* from this MJPEG stream, processes each frame for garbage detection, then re-serves the annotated video to the frontend via its own `/video_feed` endpoint.

*** B. Sensor Node (ESP32 WROOM)
- **Role**: Reads all environmental sensors and sends data via HTTP POST directly to the backend.
- **Sensors**: Turbidity, pH, and Temperature.
- **Hardware Integration**: Uses ADC1 pins (which are safe to use alongside Wi-Fi) for analog sensors.
  - Turbidity: GPIO 32
  - pH: GPIO 33
  - Temperature: GPIO 34
- **Software**: Runs `Guardian/SensorNode.ino`. Connects to the Wi-Fi hotspot, reads sensors every 2 seconds, and sends a JSON payload directly to the Python backend via an HTTP POST request.

** 2. Controller Laptop (Central Hub)
- **Network**: Runs a Wi-Fi Mobile Hotspot to host the local network.
- **Backend Server**: Runs the Python FastAPI server which receives data directly from the ESP32.

** 3. Backend Server (Python)
- **Framework**: FastAPI.
- **Data Ingestion**: Exposes an HTTP POST endpoint (`/api/sensors`) that the ESP32 WROOM calls to submit sensor data. This completely removes the need for an external MQTT broker.
- **Camera URL Registration**: Exposes an HTTP POST endpoint (`/api/camera`) that the frontend calls once to tell the backend the ESP32-CAM's MJPEG stream URL.
- **Video Proxying & Garbage Detection**: A background thread in `vision.py` pulls from the ESP32-CAM's MJPEG stream, runs garbage detection on each frame, and stores the latest annotated frame in memory. The `/video_feed` GET endpoint then re-serves this as a new MJPEG stream to the browser.
- **WebSockets**: Broadcasts the received sensor data in real-time to the frontend dashboard via the `/ws` endpoint.

** 4. Frontend Web UI
- **Technology**: HTML/CSS/JS served directly by the FastAPI backend (from `/static`).
- **Features**:
  - A modern, glassmorphic dashboard displaying real-time sensor readings (Turbidity, pH, Temperature).
  - A "Connect Stream" input where the user enters the ESP32-CAM's local IP. The frontend POSTs this URL to `/api/camera`, after which the backend begins pulling and processing the stream.
  - A live video feed `<img>` element pointed at the backend's `/video_feed` endpoint, which displays the MJPEG stream with garbage detection overlays.
  - Communicates with the Python backend via WebSockets (`/ws`) for zero-latency sensor data updates.

** 5. Full Data Flow Summary
#+BEGIN_SRC
ESP32 WROOM  ---(HTTP POST /api/sensors)---> FastAPI Backend ---(WebSocket /ws)---> Browser Dashboard
ESP32-CAM    ---(MJPEG stream :81/stream)--> vision.py thread --> /video_feed   ---> Browser <img> tag
Frontend     ---(HTTP POST /api/camera)----> FastAPI Backend  (registers the CAM URL, triggers vision.py)
#+END_SRC
